# HTML-to-PDF Skill

Convert an HTML file (with CSS, flex/grid layouts, custom fonts, print
CSS `@page` rules) into a pixel-accurate PDF using a headless browser.
Use when the downstream consumer needs a real PDF — resumes, CVs,
styled reports, documents where layout fidelity matters.

**This skill is the HTML-rendering path the `pdf` skill points to but
does not document.** The `pdf` skill owns everything else: create/merge/
split/watermark/fill forms/OCR/metadata. Use `pdf` for those; use this
skill when the source is HTML and layout must be preserved.

## When to Use

- Render a resume/CV from HTML into a clean A4 PDF.
- Produce a PDF from any styled HTML where reportlab would be slower
  and less faithful than "render the page as the browser sees it."
- The HTML already exists (hand-written, generated by another step) and
  you need a PDF out, not another HTML variant.

## When NOT to Use

- The source is not HTML — use the `pdf` skill directly.
- You need to edit text inside an existing PDF — that is the `pdf`
  skill's `references/nano-pdf-editing.md` path.
- The document is scanned/image-only — use `pdf` → `references/
oauth-extraction.md`.
- You only need a shareable URL, not a local file — consider
  `here-now` instead (publishes HTML or PDF to a live URL).

## Procedure

### 1. Verify the HTML source renders the way you expect

Open the HTML in a browser (or via `browser_exec`) and eyeball it
before rendering. Catch layout problems early — a PDF of a broken
page is still a broken page.

### 2. Render to PDF with Playwright

```python
from playwright.sync_api import sync_playwright
import os

HTML_FILE = 'resume.html'   # change to your file
PDF_FILE  = 'resume.pdf'

with sync_playwright() as p:
    browser = p.chromium.launch(
        channel='chrome',
        args=['--no-sandbox', '--disable-dev-shm-usage']
    )
    page = browser.new_page()
    page.goto('file://' + os.path.abspath(HTML_FILE))
    page.wait_for_load_state('domcontentloaded')
    page.pdf(
        path=PDF_FILE,
        format='A4',
        print_background=True,
        margin={
            'top': '14mm',
            'bottom': '14mm',
            'left': '15mm',
            'right': '15mm',
        }
    )
    browser.close()

size = os.path.getsize(PDF_FILE)
print(f'PDF created: {PDF_FILE} ({size/1024:.1f} KB)')
```

Run it with the Hermes venv Python, **not** the system `python3` on
PATH:

```bash
"C:/Users/USER/AppData/Local/hermes/hermes-agent/venv/Scripts/python.exe" \
    render.py
```

### 3. Tune page margins and page size in CSS or in `page.pdf()`

- For A4 with normal margins, the `margin` dict above is a good default.
- For full-bleed or custom paper sizes, set `format` to a known size
  (`'Letter'`, `'A3'`, `'A4'`, `'A5'`, `'Legal'`) or pass
  `width`/`height` in CSS pixels.
- Print CSS (`@page { size: A4; margin: 14mm; }`) in the HTML also
  drives the render — Playwright honors it.

### 4. Verify before handing over

- Confirm the file exists and is non-trivial in size (a blank page is
  usually under 10KB).
- For layout-critical documents (resumes, CVs), render page 1 to PNG
  and inspect:

  ```bash
  "C:/Users/USER/AppData/Local/hermes/hermes-agent/venv/Scripts/python.exe" \
      -c "
  from playwright.sync_api import sync_playwright
  with sync_playwright() as p:
      b = p.chromium.launch(channel='chrome')
      pg = b.new_page(viewport={'width': 1200, 'height': 1600})
      pg.goto('file:///path/to/resume.html')
      pg.screenshot(path='resume-page1.png', full_page=False)
      b.close()
  "
  ```

  Then call `vision_analyze(image_url='resume-page1.png', question=
  'Is this resume clean, readable, and professional? Any overflow,
  cutoff text, broken layout, or misaligned sections?')` and fix
  before delivering.

- For multi-page documents, also check the last page for orphaned
  headings or awkward breaks.

## Canva deliverability caveat

If the user asked for "put this in Canva" and you created a Canva
design via the Composio `CANVA_POST_DESIGNS` tool: the Canva API can
**create** a blank design (returns an `edit_url`), but it has **no
endpoint to add arbitrary text content** into a plain doc/presentation
design. The autofill API
(`CANVA_INITIATE_CANVA_DESIGN_AUTOFILL_JOB`) only works against a
**brand template with pre-defined data fields** — a blank doc preset
has no fields and cannot be autofilled. Canva's Magic Design / AI
features have no API endpoint — never imply they can be invoked
programmatically.

### Pre-check (run BEFORE creating the design)

Before promising any API-driven content fill, verify the account can
do it: call `CANVA_GET_USERS_ME_CAPABILITIES` and
`CANVA_ACCESS_USER_SPECIFIC_BRAND_TEMPLATES_LIST` (dataset=
`non_empty`, query=`resume`). If capabilities come back empty AND no
autofill-capable brand template exists, API fill is impossible — say
so upfront and offer the local HTML→PDF path instead. Discovering
this after creating a blank design wastes a round trip and the user's
patience.

Consequences:
- A blank Canva design created via API is an empty canvas. The user
  must open it and style/paste content manually, or you must start
  from an autofill-capable brand template.
- If the user said "do it for me" and you cannot reach the browser
  (login wall, no Chrome, harness down), the realistic fallback is:
  render HTML→PDF locally (this skill) and hand over the PDF.

## Pitfalls

- **Do not use the system `python3` (3.14) to run playwright scripts.
  Install `playwright` into the Hermes venv Python (3.11) instead.**
  The system interpreter's site-packages may not resolve cleanly and
  can collide with uv-managed installs. The venv Python is the one
  that already has playwright working.
- **`playwright install chromium` is slow and often unnecessary** when
  `channel='chrome'` works. Only run the install if Chrome is absent
  or channel='chrome' fails. Prefer `channel='chrome'` first.
- **WeasyPrint is not a usable fallback on this Windows host.** It
  installs but fails at import time trying to load GTK libs
  (`libgobject-2.0-0`, `libpango`) that are not present. Do not
  recommend WeasyPrint as a Windows fallback — go straight to the
  headless browser.
- **The browser-harness daemon must see Chrome running.** If
  `browser_exec` or a playwright launch fails with
  "no supported Chromium-family browser is running", start Chrome
  manually once, then retry. This is a daemon-state issue, not a
  Playwright bug.
- **`page.pdf()` honors the page's rendered CSS, including `@page`.
  If margins look wrong, check both the `margin` argument to
  `page.pdf()` and any `@page` rule in the HTML — they interact.**
- **Screenshots for verification use `full_page=False` by default.
  For a full-page capture set `full_page=True`, but be aware that
  tall pages produce very large PNGs.**
- **Do not claim a PDF is good without checking it visually for
  layout-critical documents.** A 60KB PDF can still have cutoff text
  or overflowing containers — file size is not a layout guarantee.

## Quick decision table

| What you have | What you need | Path |
|---|---|---|
| HTML file | PDF, layout must be faithful | This skill (Playwright → PDF) |
| Structured data (JSON/fields) | PDF with forms, tables, watermarks | `pdf` skill (`pdf_create.py`, `pdf_make_form.py`, …) |
| HTML file | Shareable URL, not a local file | `here-now` skill (publish the HTML or the PDF) |

| Existing PDF, edit text | Edited PDF | `pdf` skill → `references/nano-pdf-editing.md` |
